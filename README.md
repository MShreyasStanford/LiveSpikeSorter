# Live Spike Sorter (LSS)

Live Spike Sorter (LSS) is a GPU-accelerated real-time spike sorter for extracellular neural recordings. It streams data from [SpikeGLX](https://billkarsh.github.io/SpikeGLX/), matches incoming signals against spike templates generated by [Kilosort4](https://github.com/MouseLand/Kilosort), and outputs sorted spike events with low latency. The sorted output can drive closed-loop neurofeedback experiments via built-in networking, and an optional real-time decoder supports online classification of neural activity.

> **Recommended before your first experiment:** do a full offline test run. Replay a
> recording you already have through a SpikeGLX simulated probe, so the entire pipeline
> runs exactly as it would on the rig with no hardware attached. The
> [Offline Sorting Guide](OfflineSortingGuide.md) covers first-time machine setup and
> the per-session workflow.

## Building from Source

1. Open `OnlineSpikes.vcxproj` in Visual Studio 2022 (Build Tools, `v143` toolset).  
2. Set the `CUDA_PATH` environment variable to your CUDA 11.8 installation (e.g. `C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v11.8`).  
3. Select **Release | x64** and build the solution.  
4. If successful, you should see output in `<repo>\x64\RELEASE\OnlineSpikes.exe`

## Python Environment Setup

Python 3.10. From the repository root:

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

## Running LSS 

From your venv:
```bash
python src/Python/run_online_spikes.py
```

The GUI lets you configure one or more sorter instances, select Kilosort output directories, and optionally re-run Kilosort4 before launching LSS. You must run Kilosort4 on a short recording (10–20 minutes) to generate templates, the whitening matrix, drift matrices, and other tensors that LSS needs at runtime.


## Real-Time Output

The SDM (Stimulus Display Machine) integration sends a per-bin summary of spiking to a separate machine for closed-loop stimulus control. What gets sent depends on the processor selected in the launcher: 

1. Z-score firing trigger 
2. Logistic regression decoder trained on a previous session's `spikeOutput.txt` and event file
3. Raw per-neuron bin counts (TCP)
4. FS/RS custom stimulus trigger (used in our paper's closed-loop demo experiment). 

All except bin counts are sent over UDP. Overall functionality is limited.

For other custom use cases, the spike streams can be networked via UDP, configurable under "Spike Stream" in the launcher. When enabled, each sorted spike is sent as soon as its batch is processed. A receiver can parse these packets using your preferred interface ([Python example](src/Python/lss_receiver.py)).
